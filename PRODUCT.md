# PRODUCT.md

## What One Pawn is

One Pawn is a focused chess learning platform for players who want to actually improve, not be entertained. It combines a browser-based engine, a structured learn mode, a spaced-repetition opening trainer, and an AI coach that explains mistakes in plain language.

It is not a social platform. It is not a competitive ladder. It is not a chess destination. It is a tool you open when you want to get better, and close when you're done.

## Positioning

The chess software market is dominated by two platforms: chess.com (gamified, ad-heavy, aggressive monetisation, overwhelming for beginners) and Lichess (excellent but engineered for chess players who already know what they want). Both serve their audiences well. Neither serves the person in the middle: a casual or beginner player, aged roughly 16-30, who has tried chess.com, felt overwhelmed by the noise, and quietly stopped opening the app.

One Pawn is built for that person.

## Target users

**Primary:** Casual and beginner players aged 16-30 who bounced off chess.com. They want to improve but find current tools intimidating, cluttered, or condescending. They value a clean interface and honest feedback over rewards and streaks.

**Secondary:** Intermediate players (roughly 1200-1600 rating) who want serious analysis and structured training without paying a monthly subscription for features they don't need.

**Tertiary:** Recruiters, admissions committees, and technically-inclined viewers who encounter One Pawn as a portfolio piece and evaluate it on technical depth.

The tertiary audience is real and shapes decisions about code quality, architecture visibility, and public repo presentation, but never at the expense of the primary user.

## Core identity

One Pawn is defined by four commitments, in priority order:

1. **Focused, not gamified.** No confetti, no trophies, no "you're on fire" notifications, no daily login rewards. Progress is shown through data, not dopamine.

2. **Honest, not encouraging.** The coach tells you what went wrong in real terms. Bad moves are called bad. Improvement is shown when it happens and not manufactured when it doesn't.

3. **Structured, not open-ended.** Learn mode has a defined path. Openings graduate from learn to reinforce through explicit criteria. Users always know where they are in the progression.

4. **Adult, not childlike.** The visual and verbal tone treats the user as a capable adult. Muted palette, restrained typography, a coach voice that is patient and dry rather than falsely enthusiastic.

Every feature decision is measured against these four. Features that dilute any of them are cut or deferred, regardless of how popular they would be.

## Core features

**Play against the engine.** A C++ engine, compiled to WebAssembly, runs entirely in the browser. Adjustable difficulty via search depth. Multiple time controls. Games are saved to a personal history if the user is logged in.

**Learn mode.** Structured lesson tracks covering fundamentals, the most important openings, tactical patterns, and endgame basics. Each lesson is interactive: the user makes moves, the platform validates and explains. Lessons have defined completion criteria.

**Reinforce mode (opening SRS).** Openings that have been learned enter a spaced repetition queue. The user is presented with due reviews each session. Correct runs push the interval further out. Mistakes reset the interval and drop the ease factor. The algorithm decides what is due; the user does what is presented.

**AI coach.** After each game, the engine re-evaluates every position and classifies moves. The three most critical moments are surfaced with natural language explanations generated by an LLM grounded in engine evaluation. The user can ask follow-up questions about specific positions. Coach usage is metered. Automatic post-game analysis is available to all users at a defined free limit (initially one full LLM-powered overview or forecast per week); unlimited use will be a paid tier feature if monetisation is introduced. Basic engine-based classification (move labels, evaluation graph) remains available on every game with no limit.

**Mistake pattern tracking.** Across saved games, the platform identifies recurring failure modes. Not per-game analysis, but longitudinal: "you have hung a knight to a fork in 7 of your last 20 games," "your accuracy drops significantly in positions with an open centre." This turns game history into a diagnostic. Pattern detection is implemented in plain code using engine data and heuristics, not the LLM. The LLM is only involved when the user asks a follow-up question about a specific detected pattern.

**Drill mode.** Any position from a saved game or lost puzzle can be replayed against the engine repeatedly. The user practices the specific moment they struggled with, not the general skill.

## Deferred features (post-launch, if traction)

These are on the roadmap but explicitly not part of the initial product. Documented here so scope is clear.

- **Play style archetypes.** Longitudinal game analysis produces a "chess personality" (e.g., The Butcher, The Architect) with a shareable card. Marketing surface, not core value.
- **Shareable game links.** One-click share of a game with coach analysis attached. Recipient sees a read-only viewer.
- **Play a friend via link.** A logged-in user can generate a private game invite link. Recipient joins via the link, both play in real-time. No matchmaking, no discovery, no ratings.
- **Public opening repertoires.** Users optionally publish their opening prep as browseable pages. No comments, no threads.
- **Native mobile applications.** Once the responsive web app is stable and validated, native iOS and Android apps will follow, likely built in React Native to reuse the existing frontend codebase.

## Explicitly not features

The following will not be built. They are not deferred, they are rejected.

- **Discussion forums or community features.** Moderation cost, legal exposure, and identity dilution. Existing communities (r/chess, Discord servers) serve this need better than One Pawn could.
- **Streaks and daily rewards.** Contradicts the "focused, not gamified" commitment.
- **Rating ladders, leaderboards, or algorithmic matchmaking with strangers.** One Pawn does not match users against each other. Playing a friend via a shareable link is permitted and planned for a later phase, but there is no discovery, no ratings, no public ladder.
- **Broad SRS beyond openings.** Tempting to extend spaced repetition to tactics and endgames. Deferred indefinitely. Openings SRS gets tuned properly before any expansion is considered.
- **Live streaming, broadcasts, tournament coverage.** Not our audience.

## Monetisation stance

Free during alpha and beta. If the user base grows meaningfully after public launch, a paid tier will be introduced. Free tier will always include: full engine strength (no depth cap), unlimited local play, basic learn mode, unlimited SRS reviews, engine-based post-game classification. Potential paid features: unlimited LLM coach analysis, unlimited "ask the coach" questions, full mistake pattern history beyond a defined retention window, drill mode expansions, cross-device sync of drill state. No dark patterns, no artificial restriction of core play. If a paid tier is introduced, existing free-tier features will not be moved behind the paywall.

Decision on monetisation is deferred to post-beta. The architecture will support subscription features without modification.

## Voice and tone

**The coach's voice** is patient, direct, slightly dry. A chess teacher who has seen every mistake before and just wants the student to understand. No false enthusiasm. No congratulations for basic actions. No memes. Corrections are matter-of-fact.

Example, bad: "Oops! That knight move wasn't the best. Try again, you've got this!"
Example, good: "Nf6 loses a tempo here. Black wants to keep pressure on d4, and Nf6 releases it. Nc6 is more common because it defends e5 while preparing kingside development."

**The interface voice** is minimal. Buttons say what they do ("New game," "Save," "Learn"). No copywriter flourishes.

**The written content voice** for lesson explanations, coach responses, and error messages uses British spelling, American grammar, short sentences, no em-dashes as filler, professional but human.

## What success looks like

**Alpha (private):** One Pawn is playable, the engine works, games save, auth works. Rough edges everywhere. Used by the developer and 3-5 trusted testers.

**Beta (limited public):** Learn mode is complete for the covered content. Reinforce mode works with tuned SRS. Coach gives useful post-game feedback within its metered limit. Used by 50-200 people, mostly from targeted outreach (chess Discord servers, r/chess, university friends).

**Public web launch:** All Phase 1-3 features stable. Documentation exists. Legal documents in place. Portfolio-ready.

**Native mobile launch:** iOS and Android apps published to their respective stores after web app validation. Developer accounts purchased at the appropriate phase.

**Sustained success (post-launch):** Users who complete the learn track and engage with reinforce mode for 4+ weeks. Measured by return sessions, not raw signups. If someone signs up and never comes back, that is not a success even if signups are high.

## Non-goals

- Being the biggest chess platform
- Being a chess destination
- Replacing chess.com or Lichess
- Generating significant revenue in year one
- Serving grandmasters, streamers, or competitive tournament players

## The one-sentence pitch

A focused chess trainer that treats you like an adult learner: clean interface, spaced-repetition openings, and an AI coach that explains your mistakes instead of just labelling them.
